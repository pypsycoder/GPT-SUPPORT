## 5. Миграция `20260830_01`

**Что делает** (UPDATE, без DELETE/TRUNCATE):

| Таблица | Поле | Строк |
|---|---|---:|
| `education.lessons` | `code` + `order_index` | 17 |
| `education.lesson_tests` | `code` | 17 |
| `practices.practices` | `id` + `module_id` | 12 |
| `practices.practice_completions` | `practice_id` (follow-update) | 9 |

**Не трогает:** `lesson_progress`, `lesson_test_results` (ссылаются на суррогатные id),
тексты карточек/вопросов/инструкций.

**Ключи сопоставления:** уроки/тесты ищутся по СТАРОМУ `code` (unique), практики — по старому
строковому `id`. Не по суррогатному integer-`id` — он свой в каждой среде. Если строки нет —
UPDATE трогает 0 строк (безопасно).

**FK `practices.practice_completions.practice_id`** (`ON UPDATE NO ACTION`): выбран путь
**снять FK → обновить `practices.id` и `practice_completions.practice_id` → пересоздать FK**
с тем же `ON DELETE CASCADE`. Обосновано в комментарии ревизии: атомарно в транзакции ревизии,
семантика FK сохраняется (без перехода на `ON UPDATE CASCADE`, который пережил бы миграцию),
полностью реверсивно.

**Карты старых↔новых значений** зашиты константами в файле ревизии (не читаются из `content/`).

**`downgrade()`** — точная инверсия (та же таблица `LESSONS/LESSON_TESTS/PRACTICES`, обход в
обратную сторону).

### 9.3 «Агент должен знать, какие практики делал и что помогло» — было частично, доработано

**Было:** `_get_practices_summary` ([`app/llm/context_builder.py`](app/llm/context_builder.py),
секция профиля «Практики», её видит `SupervisorStage` каждый ход через
`build_context_bundle_optimized`) отдавала только:
- «Практики выполнено за 7 дней: N» — голый счётчик;
- «Доступные практики: …» — 5 активных практик, **generic-список, не персональный**.

`mood_after` в БД писался, но **никто его не читал** — ни агент, ни `morning_service`, ни бейджи,
ни профиль.

**Стало:** `_get_practices_summary` переписана — за 30 дней, с JOIN на практику:
```
Практики: за 30 дней: Физиологический вздох — 1×, последний раз 28.08, по ощущениям: стало легче,
          отмечал облегчение после: Физиологический вздох,
          доступные: … (только если пациент пробовал < 3 практик)
```
- `mood_after` усредняется по практике → «стало тяжелее / без изменений / стало легче»;
- `avg(mood_after) ≥ 2.5` → практика попадает в строку «отмечал облегчение после» — на неё
  агент может опираться как на рабочую для этого пациента;
- generic-список «доступные» показывается только новичку (< 3 практик за месяц), иначе шум.

`pytest` — 512 passed. `morning_service` / проактивный контур пока получают только счётчик —
если нужно и там, отдельным шагом.

**Ограничение:** «помогло» выводится только из `mood_after` (нет `mood_before`), сигнал слабый —
это «после практики стало не хуже», а не измеренный эффект.
